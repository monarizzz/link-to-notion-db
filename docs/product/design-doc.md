# Design Doc

## Overview (概要)

開発を通じて得たいこと

- 自分の課題を捉え、それに沿ったプロダクトを作る
  - サマーインターンで学んだ手法を試す
- BE開発を通じて、未理解だった領域の知識を得る

## What we provide (何をつくるのか)

> ここでは具体的にどのようなサービスを作るのかを記載します。作ったものがどのように機能するのか、サービスが届ける具体的な価値に関してまとめます。あなたが作るものを最もシンプルな言葉で表現してください。

**具体的にどのようなサービスを作るのか（誰の・何を・どうするか）：**

- **誰の：** 自分自身
- **何を：** 学習のペースが安定せず、途切れると再開にも負担がかかる状態を
- **どうするか：** 作業時間や状態の振り返り、計画・再開の支援を通じて、無理なく継続できるペースを見つけ、維持・回復できるようにする

## BackGround (バックグラウンド)

> なぜこの取組みを行うと決めたのか、どのような情報が意思決定を促したのか、ユーザージャーニーマップやワークで考えた一連のプロセスも参考に背景をまとめてください。

現状の課題

- 突然不調になることがある
  - 不調に気づかない、またはやる気の問題だと疑う
  - 自分を責めたり、効果のないアプローチを繰り返して落ち込む
  - さらに学習から離れてしまう
- 作業時間に波があること
  - 「やろうと思ったことができなかった」となると凹んでしまって、さらに作業に手がつなかなくなる
  - 長い期間離れてしまうと、タスク時自体を思い出すのに時間がかかってしまい、余計に手がつかなくなる

価値観

- 限られた時間や体力を最大限活用したいという欲求がある
- 体調に波があるため作業できる時に最大限学習したい

**理想の状態：**

- 取り組んだことを確認し、達成感や次への意欲につなげる
- 作業時間とその後の状態から、継続できるペースを探す
- 不調につながりそうな要素を事前に確認し、その日の予定や過ごし方を調整できる

## User Story (ユーザーストーリー)

> このセクションにはこの取組みを届ける相手 (ユーザー) の心境、動機を書きます。
> また、どのようにユーザーの動機が満たされ、どのような状態になっていることを想定しているかを書きます。

**ユーザー：**

- **自分自身（：どうあると嬉しいか）**
  - 作業開始前：すぐに始められる状態
    - 計画する習慣がなく、習慣化したい
      - 毎日の意志や頑張りだけに頼らず、継続しやすい状態が必要
    - 状態を踏まえて、作業量や休憩、取り組む予定を調整したい
    - 優先順位が明確
  - 作業中：長く続くように
    - 過集中に気づかなくても、必要な休憩や食事・水分補給に移れる状態
      - 状態や心理的負担に合わせて無理のない配分にする
    - タスクにかかる想定時間から残りの作業時間がわかる状態
      - 今のタスクが終わるまでの時間
      - 今日予定している作業が終わるまでの時間
      - 次に休憩するまでの時間
  - 作業終了後：頑張った内容がすぐにわかる状態
    - 作業した時間・取った休憩時間がわかる
    - 学習した内容をDocsやGitHubをわざわざ探しに行かなくても、作業時間を振り返る流れで、その日取り組んだ内容が目に入り、思い出すきっかけになる
  - 作業を再開する時
    - 以下の情報がわかる
      - 何をしていたか
      - 次に何をするか
      - どれくらい時間がかかるか
      - どんな心理的負担があるか
  - 気分が乗らない時
    - 短時間で終わり、所要時間と手順が明確で、心理的負担が少ない事務作業から手を動かし、学習に入るきっかけを作りたい

**心境・動機：**

- 作業開始前：
  - タスクを把握するのがしんどい
  - どのくらいの時間や心理負担がかかるかという情報から1日の計画を立てたい
- 作業中：
  - 知らない間に疲れすぎていた・ご飯を食べ忘れていた・運動し忘れていたなどの不調によって作業時間が減るのを避けたい
  - あとどのくらい頑張れば終わらせられるのか知って一踏ん張りしたい
- 作業終了後：
  - 頑張った量が視覚的にわかることで達成感を得たい
    - 収集ゲームなどで画面が埋まっていく感覚に近い
  - 何をやったか簡単に振り返りをすることでより定着させたい
- 再開する時：
  - ほぼゼロから把握し直すことで、タスクが大きく見え、戻りづらくなる
- モチベーションがない時
  - 考えずに手を動かせる軽い作業から入り、学習に取りかかる弾みをつけたい
  - 少しでも取り組めるものがあれば手をつけたい

**目指す状態（サービス作成後の状態）：**

- 次に取り組むこと、これまで取り組んだこと、自分の状態を確認でき、学習を続ける・再開する際の心の拠り所になる

## Alternatives Considered (検討した代替案)

> ゴール (Why) を満たすための取り組み (How) は、あなたが要件定義した How 以外にもいろいろなアプローチがあり得るはずです。どのような手段を他に検討したのか、あるいは取り得るのか、またそれを選択せずに今回のアプローチに決定した理由をまとめてください。

- AIに1日のタスクを提案させる
  - API料金がかかる可能性がある（要調査）
- Notion Calenderに予定と作業時間を管理＋既存のタイマー機能（現状）：大きく困っていない
  - メリット：視覚的にわかりやすい・操作性が良い・開発せずに済む・Googleの予定を連携しているためそのまま表示できる
  - デメリット：ポモドーロやタイマーなどの機能は Calender単体では不可能・タスクの把握は可能だが、Notion DBに入れる必要がある・Notion DBの制約が設計上よくない
