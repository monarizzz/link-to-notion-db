# コミットの原則

コミットの分け方・並べる順序・メッセージの書き方。

## 粒度

### 1 コミット = 1 つの論理的変更

- 論理的変更とは、レビュアーが 1 つのまとまりとして理解できる単位
- 複数ファイルにまたがってもよい。逆に 1 ファイル内でも関心事が違えば分ける
- 判断基準: 「このコミットを revert したとき何が失われるか」を一文で言えるか

### 型チェックが通る単位で切る

- 各コミットの時点で `pnpm typecheck` が通ること
- 理由: `git bisect` で壊れたコミットを特定できるようにするため
- やむを得ず途中のコミットが壊れる場合は、そのことを本文に書く

### 小さすぎても分けない

- typo 修正 1 件だけを独立コミットにするのは分けすぎ
- 関連する小さな修正はまとめる。目安は diff 全体を 30 秒で把握できること

## 分類

### 生成物と手書きを分ける

- shadcn CLI が生成したコンポーネント（`apps/web/src/libs/shadcn/`）は、手書きのコードと別のコミットにする
- 例外: `pnpm-lock.yaml` は `package.json` と同じコミットにする。食い違うと `pnpm install --frozen-lockfile` が止まる

### 新規と既存の変更を分ける

- 既存コンポーネントへの変更は、新規コンポーネントの実装と別のコミットにする

### デザインファイルとコードを分ける

- `.pen` ファイルの変更は実装のコミットに混ぜない。差分をレビューで読めないため

### リファクタと機能追加を混ぜない

- 機能追加の前にリファクタが必要なら、先にリファクタのコミットを作る
- 見た目と振る舞いが変わらないものをリファクタとする。Storybook の表示やテスト結果が変わるならリファクタではない

### テストと実装

- 既定はテストと実装を 1 コミットにする。`.stories.tsx` もコンポーネントと同じコミットに置く
- バグ修正は「再現するテストを追加する」→「修正する」の 2 コミットにしてもよい。その場合は、1 つ目のコミットでテストが落ちることを本文に書く

## 順序

### 依存の下から上へ

1. ツール・設定（`package.json`、ESLint 設定、`.github/workflows/`）
2. 汎用ライブラリ・設定（`apps/web/src/libs/`）
3. 外部サービス連携（`apps/web/src/infra/`）
4. 共通コンポーネント（`apps/web/src/commons/`）
5. 機能コンポーネント（`apps/web/src/features/`）
6. ルーティングの結線（`apps/web/src/app/`）
7. ドキュメント（`AGENTS.md`、`README.md`、`docs/`）

各コミットが、それより前のコミットだけに依存するように並べる。
上の層を先にコミットすると、そのコミット単独では import 先が無く型が付かない。

### バグ修正は先に切り出す

- 機能追加の途中でバグを見つけたら、先に修正コミットを作る。別 PR に出しやすくなる

## メッセージ

件名は `<種別> <内容>`（例: `fix 許可したGoogleアカウントのみログインできるように制限する`）。

- 何を・どこに・どうしたかを書く。`fix` `修正` だけで終わらせない
- 判断を伴う変更は、本文になぜそうしたかを書く

### 種別

ブランチ名・PR・Issue の件名でも同じ種別を使う。

| 種別 | 使う場面 | Issue ラベル |
| --- | --- | --- |
| `feat` | 機能の追加・変更 | `enhancement` |
| `fix` | 不具合の修正 | `bug` |
| `refactor` | 挙動を変えないコードの整理 | `refactor` |
| `docs` | ドキュメントのみの変更 | `documentation` |
| `ci` | CI・GitHub Actions の変更 | `ci` |
| `chore` | 上のどれにも当たらない保守作業（依存更新・設定など） | `chore` |

## アンチパターン

- ❌ `git add -A && git commit -m "fix"` — 何が入ったか分からない
- ❌ 「WIP」「一旦ここまで」コミット — PR を出す前に整理する
- ❌ リファクタ・バグ修正・機能追加が入った巨大コミット — 後から分けられない
- ❌ `apps/web/src/app/` の結線を、結線先のコンポーネントより前にコミットする
